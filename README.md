# FixView Browser — Web デモ

Android 自動化（MacroDroid / Tasker など）向けブラウザアプリの、動作デモです。
Next.js だけで作られており、データベースは使いません（保存先はブラウザの localStorage のみ）。

PC で開くとスマホの外観の中でアプリが動き、スマホで開くとアプリがそのまま全画面で動きます。

## 起動方法

Node.js 20.9 以上が必要です。

```bash
npm install
npm run dev        # http://localhost:3000
```

動作が重い PC では、ビルドしてから起動するほうが軽快です。

```bash
npm run build
npm run start
```

- 同じ LAN 内のスマホで見るときは `http://<PCのIPアドレス>:3000` を開きます（`next.config.ts` の `allowedDevOrigins` でプライベート IP を許可済み）。
- 既定では PC のすべてのネットワークから接続できる状態で待ち受けます。自分の PC だけで見る場合は `npm run dev -- -H 127.0.0.1` のようにホストを指定してください。
- 保存データを消して最初からやり直すには、アプリの「設定 → データ → すべて初期化」を使います。

## 画面の見方

| 場所 | 内容 |
| --- | --- |
| 中央（スマホ） | アプリ本体。プロファイル画面が最初に開きます |
| 左パネル（PC のみ） | 端末シミュレーター。機種、ナビゲーションバー、端末の文字サイズ・表示サイズを切り替えます |
| 右パネル（PC のみ） | 座標インスペクター。表示エリアとマークの絶対座標、4 機種の比較表、カーソル位置の座標を表示します |

スマホ（幅 560px 以下）で開いた場合はパネルが出ない代わりに、「設定 → 座標情報」で同じ数値を確認できます。

## 依頼内容との対応

| 依頼内容 | デモでの実装 |
| --- | --- |
| ① 複数プロファイルの登録・管理・切替・リセット | プロファイル画面に 30 枠。番号タップで切替、未登録の番号をタップすると登録、「リセット → 番号」で Cookie・キャッシュ消去または登録削除。長押しで詳細 |
| プロファイルを使わない通常ブラウザ | プロファイル画面の「ブラウザ」。このモードだけに Cookie・キャッシュの「リセット」ボタンがあります |
| ② 機種に依存しない表示エリアの固定 | 「設定 → 表示エリアの固定」で px 固定 / dp 固定 / 固定なし を切替。幅・高さ・位置を数値で指定できます |
| px と dp のどちらで固定すべきかの検討 | 右パネルの比較表で、方式ごとに 4 機種の座標がどうなるかを確認できます（下記参照） |
| ③ 表示エリア外の座標基準マーク | 表示エリアの四隅の外側に配置。形・色・大きさ・表示する角を設定でき、中心座標をインスペクターに表示します |
| ④ 端末の文字サイズ・表示サイズを反映させない | 「設定 → 端末設定の影響」。左パネルで端末側の設定を変えて、影響の有無を確認できます |
| ⑤ レイアウトを壊さない画像非表示 | ツールバーの「画像非表示」。画像を読み込まず、同じ大きさの枠に置き換えます |
| 設定（表示エリア・色合い・濃淡） | 「設定」画面。背景色はブラウザ画面とプロファイル画面で別々に指定できます |

依頼には無い追加要素:

- **読込状態インジケーター** — 読込中は橙、完了で文字色になる四角。マクロが 1 ピクセルの色で読込完了を待てます。
- **タップ位置の座標表示** — タップした位置の画面座標（px）を表示します。
- **全機種に収まる最大サイズの自動計算** — 対象 4 機種のバーの高さから、収まる最大の表示エリアを求めます。
- **設定の書き出し / 読み込み** — 表示エリア・色・マーク・プロファイル一覧を JSON で別の端末へ移せます。

## px 固定と dp 固定

このデモでは、Web の表示エリアだけでなく、ツールバーやプロファイル番号を含む **アプリ画面全体を 1 枚の固定キャンバス** として描画しています。プロファイルの切替など、アプリ自身のボタンもマクロで押せるようにするためです。

| 方式 | 見た目の大きさ | ピクセル座標 |
| --- | --- | --- |
| px 固定 | 高解像度の機種では小さくなる（1080px 幅の機種で 67〜71%） | 全機種で同じ |
| dp 固定 | 全機種でほぼ同じ | 画面密度に比例して変わる |
| 固定なし | 通常のブラウザと同じ | 機種ごとに表示範囲も変わる |

既定値（720 × 1120 px、上端から 100 px、左寄せ）では、4 機種すべてで表示エリアが (0, 300) – (720, 1420) になります。

## デモがシミュレーションしている範囲

Web ブラウザ上のデモなので、次の点は実機アプリの動作を模したものです。

- **機種の仕様** — 解像度は公表値ですが、画面密度・ステータスバーとナビゲーションバーの高さ・角の丸みは代表値です（`src/lib/devices.ts`）。実機で測定して置き換える前提です。
- **Cookie・キャッシュの分離** — 内蔵のデモページ（`demo://…`）に対してのみ働きます。外部サイトの Cookie は、デモを開いているブラウザ自身のものが使われます。キャッシュ容量は想定値です。
- **画像非表示** — 内蔵のデモページにのみ働きます。節約量の表示は、各画像に設定した想定サイズの合計です。
- **外部サイトの表示** — iframe で表示するため、埋め込みを拒否するサイト（Google、Yahoo! など）は開けず、説明ページに切り替わります。実機アプリは WebView で直接表示するので、この制限はありません。
- **会員ログインのロボット検証** — 見た目だけの模擬ウィジェットで、何も検証しません。

## 実機アプリで別途確認が必要なこと

- **Cloudflare などのボット検証を通過できるか。** Web デモでは確認できません。表示エリアを固定した WebView を載せた検証用 APK で、最初に確認する必要があります。
- 機種ごとの実際の画面密度とバーの高さ。
- ブラウザエンジン（Chrome / WebView）の更新方法。

## 構成

```
src/
  app/
    page.tsx                 アプリ本体（シェル）
    sites/                   内蔵デモページ（スタート、ニュース、会員ログイン、座標テスト）
    sites/img/[name]/        デモ用イラストを SVG で生成
    api/frame-check/         外部サイトが iframe 表示を許可しているかの確認
  components/
    shell/                   スマホ画面、プロファイル画面、ブラウザ画面、設定、PC 用パネル
    site/                    デモページ共通の部品（プロファイルの Cookie、画像の差し替え）
    ui/                      スイッチ、スライダーなどの入力部品
  lib/
    geometry.ts              レイアウト計算（px / dp 固定、座標、収まり判定）
    devices.ts               対象機種の仕様
    store.ts                 状態管理と localStorage への保存
    bridge-*.ts              シェルとデモページの連携
```

依存パッケージは Next.js と React のみです。UI ライブラリ、アイコンライブラリ、CSS フレームワークは使っていません。
